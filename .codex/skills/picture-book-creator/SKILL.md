# 儿童绘本生成系统

把用户的模糊想法，分阶段转化为完整的可出版级儿童绘本。

## 核心原则

- 面向儿童：简洁、温暖、清晰
- 避免复杂隐喻、成人化表达和抽象说教
- 必须匹配目标年龄段的理解能力
- 如果用户的初始 Prompt 已包含足够信息（年龄段、主题、主角等），直接提取并跳过对应的收集步骤，不要重复提问已知信息
- 信息不足的维度才需要追问
- 阶段 3→4（可读性测试）始终自动衔接，不暂停

## 固定参数

这些参数不需要询问用户，在所有绘本中保持一致：

- **开本**：正方形 210×210mm（国际主流儿童绘本尺寸）
- **图像比例**：1:1（传给 image-generation skill 时使用 `--ratio 1:1`）
- **排版**：全出血大图，故事文字直接由图像模型渲染在画面中（可放置在任意位置，根据构图需要选择最佳位置）
- **封面**：第 0 页，展示标题 + 主角 + 核心场景元素
- **无扉页、无封底**

---

## 阶段 1：需求收集

使用交互式提问收集以下信息。提供预设选项让用户快速选择，同时允许自定义。

**必须收集的维度：**

| 维度 | 预设选项 | 说明 |
|------|---------|------|
| 年龄段 | 0-2 岁 / 2-4 岁 / 4-6 岁 / 6-8 岁 | 决定语言复杂度和页数 |
| 主题 | 用户自由输入 | 故事的核心主题 |
| 主角 | 用户自由输入 | 主角的基本概念（如"一只小兔子"） |
| 画风 | 经典水彩 / 蜡笔涂鸦 / 拼贴艺术 / 手绘线条淡彩 / 日系柔和 / 北欧简约 / 扁平矢量 / 复古卡通 / 数字绘画 / 民间艺术 | 参考 `references/style-presets.md` 中的预设和年龄适配表 |
| 色调 | 暖色柔和 / 马卡龙淡彩 / 鲜艳对比 / 自然大地色 | 全书色彩方案 |
| 情绪基调 | 轻松幽默 / 温馨治愈 / 冒险好奇 | 故事情感基调 |
| 教育目标 | 用户自由输入（可选） | 如"学会分享""认识颜色" |
| 禁忌项 | 用户自由输入（可选） | 需要避免的元素 |
| 语言 | 用户指定 | 故事文案使用的语言 |
| 页数 | 根据年龄段自动推荐，用户可调整 | 参考 references/age-standards.md |

**智能收集策略：**
- 如果用户的初始 Prompt 已经提供了部分维度的信息，直接提取使用，不要重复询问
- 只对缺失的维度进行追问
- 如果所有关键维度（年龄段、主题、主角、画风）都已明确，可以直接输出需求确认摘要进入下一阶段
- 输出需求确认摘要时，标注哪些是从用户输入中提取的，哪些是自动推荐的，让用户快速确认或调整

## 阶段 2：故事方案

基于需求输出 **3 个绘本故事方向**，每个方向包含：

1. **标题**（草案）
2. **一句话概要**
3. **核心冲突 / 转折点**
4. **适龄评估**（参考 `references/age-standards.md`）：
   - 语言复杂度是否匹配目标年龄
   - 视觉可表现性：场景是否容易画出来，角色动作是否具体
   - 教育目标覆盖度：是否自然融入而非说教
   - 页数适配：情节是否能在目标页数内自然完成

展示 3 个方向后，等待用户选择一个方向（或提出修改）。

---

## 阶段 3：分页脚本

将选定故事拆为逐页脚本。第 0 页是封面，第 1 页 ~ 第 N 页是正文。

**每页必须包含以下字段：**

```
## 第 X 页

**text**：（朗读文字——严格遵守年龄段字数限制）
**scene**：（画面场景描述）
**action**：（角色正在做什么）
**emotion**：（角色的情绪状态）
**composition**：（构图指引——全景/中景/特写、视角方向、文字放置位置和排版方式）
```

**封面页（第 0 页）特殊要求：**
- text 字段填写书名标题
- scene 包含主角 + 核心场景元素
- composition 指定标题文字的放置位置、字体风格和大小（通常在画面上方或中央醒目位置）

**脚本撰写原则：**
- 严格遵守 `references/age-standards.md` 中对应档位的所有硬约束（字数、句式、对话、角色数等）
- 参考该档位的示例页格式

脚本完成后，保存到 `output/<topic>/script.md`，然后**自动进入阶段 4 可读性测试**（不需要等待用户确认）。

---

## 阶段 4：可读性测试（自动执行）

紧接阶段 3，按照 `references/age-standards.md` 中「可读性校验清单」逐项检查（语言、情节、节奏、视觉可画性、安全五大类）。

**流程：**
1. 对照当前档位的硬约束和校验清单，逐项标注 ✓ 或 ✗
2. 不通过项附说明和修改建议，**直接修改脚本**并重新检查，直到全部通过
3. 全部通过后，输出最终版脚本，等待用户确认

## 阶段 5：角色与风格设定

这一步的输出将**持久化到文件**，在后续生成图像 Prompt 时作为锚定前缀使用。

### 角色设定表

为故事中出现的每个角色输出详细设定，保存到 `output/<topic>/characters.md`：

```markdown
# 角色设定表

## [角色名]

- **物种/类型**：
- **体型比例**：（如"头身比 1:2，圆润体型"）
- **外貌特征**：（如"大眼睛、圆脸、短耳朵"）
- **服装**：（颜色、款式、标志性配饰）
- **标志性特征**：（如"左耳有一个小缺口""总是戴着红色围巾"）
- **Prompt 锚定短语**：（将以上外貌、服装、标志性特征压缩为一段英文描述，每页生图时**原封不动复制**，禁止改写或概括。例如："A white baby rabbit with large round dark brown eyes, pink blush cheeks, long white ears with pink inner ears, a small tuft of fur sticking up on the left ear tip, wearing a warm yellow pinafore dress with a small daisy embroidered on the chest pocket"）
- **表情参考**：
  - 开心：
  - 难过：
  - 惊讶：
  - 害怕：
  - 生气：
- **负面约束**：（角色绝对不应有的特征，如"不要尖牙""不要暗色调服装"）
```

**校验：** 保存 `characters.md` 前，确认每个角色的「Prompt 锚定短语」字段非空且为英文。这是角色一致性的关键——缺少此字段会导致阶段 6 每页角色外观不一致。

### 风格设定表

基于用户在阶段 1 选择的画风，从 `references/style-presets.md` 中提取对应的 Prompt 模板和负面约束作为基础，
再根据本书的具体需求（色调、情绪、主题）进行定制，保存到 `output/<topic>/style.md`：

```markdown
# 风格设定表

- **基础风格**：（选用的预设风格名称）
- **Prompt 前缀**：（从 style-presets.md 提取的完整 Prompt 模板，可微调）
- **主色调**：（如"暖黄 #F5D78E、浅绿 #A8D8B9、天蓝 #87CEEB"）
- **辅助色**：
- **强调色**：
- **负面约束**：（从 style-presets.md 提取的负面约束 + 自定义补充）
```

保存文件后，等待用户确认。

## 阶段 6：图像 Prompt 生成与批量生图

### 6.1 生成图像 Prompt

为每一页（第 0 页封面 ~ 第 N 页）生成完整的图像生成 Prompt。

**每页 Prompt 的结构（严格按此顺序拼接）：**

```
[风格前缀]
读取 output/<topic>/style.md 的内容，提取画风、色调、线条、背景、光影、氛围关键词，
拼接为一段风格描述。

[角色描述]
从 output/<topic>/characters.md 中，选取**本页出现的角色**，
**原封不动复制**其「Prompt 锚定短语」（禁止改写、概括或重新措辞），
然后追加当前情绪对应的表情描述。
锚定短语是角色一致性的关键——每页必须使用完全相同的文本。

[场景与构图]
基于阶段 3 脚本中本页的 scene + action + emotion + composition，
转化为具体的画面描述。

[文字渲染指令]
指定本页故事文字的内容、放置位置、字体风格、大小和颜色，
确保文字与画面融合且清晰可读。

[负面提示词]
合并角色负面约束 + 风格负面约束，加上通用负面词：
"no watermark, no signature, no realistic photo, no 3D render（除非风格要求）"
```

**封面页额外要求：**
- Prompt 中明确指定标题文字内容、位置、字体风格和大小
- 标题文字应醒目、与画面风格统一，通常放在画面上方或中央

**正文页文字渲染：**
- 每页 Prompt 中包含该页的朗读文字内容
- 指定文字放置位置（根据构图选择画面中最合适的区域，避开主体）
- 指定文字风格（字体、大小、颜色），需与全书风格统一且清晰可读

生成后把每页 prompt 保存为独立文本文件：

```
output/<topic>/prompts/0.txt
output/<topic>/prompts/1.txt
...
output/<topic>/prompts/N.txt
```

文件名必须与页码一致，便于批量脚本生成同编号 PNG。

### 6.2 批量生成图片

所有页面的 Prompt 准备完毕后，通过项目脚本批量调用 `image-generation`。

**执行方式：**

```bash
bun run images -- \
  --prompts output/<topic>/prompts \
  --output output/<topic> \
  --concurrency 2
```

脚本会读取 `prompts/<page_number>.txt`，输出 `output/<topic>/<page_number>.png`，其中 `<page_number>` 从 0（封面）开始编号。

可选参数：
- `--concurrency`：默认 2，范围 1-2
- `--quality`：传给 image-generation，默认 `high`
- `--min-kb`：输出文件最小体积校验阈值，默认 100

**并发限制：** 默认最多同时执行 **2 个**生成任务，且不要把 `--concurrency` 设置为大于 2。遇到 429 时，将 `--concurrency` 降到 1 后重试失败页。

**单页重试：** 修改对应 `prompts/<page>.txt` 后，可以直接运行：

```bash
Get-Content -Raw output/<topic>/prompts/<page>.txt | bun run image -- --output output/<topic>/<page>.png --ratio 1:1
```

### 6.3 验证

批量脚本完成后，检查：
1. `output/<topic>/` 目录下是否有 0.png ~ N.png 共 N+1 个文件
2. 每个文件大小是否 >100KB（<100KB 视为生成失败）
3. 对失败的页面，报告失败原因并提供重试选项

验证通过后，自动进入阶段 7。

## 阶段 7：生成 EPUB 电子书（自动执行）

图片验证通过后，自动将所有页面打包为 EPUB 电子书。

**执行方式：**

运行打包脚本：
```bash
bun run .codex/skills/picture-book-creator/scripts/generate-epub.ts \
  --input output/<topic> \
  --title "<书名标题>" \
  --author "<作者名>" \
  --lang <语言代码>
```

参数说明：
- `--input`：图片目录路径（`output/<topic>`）
- `--title`：阶段 3 确定的书名标题
- `--author`：默认 "AI Picture Book Creator"，用户在阶段 1 指定则使用用户值
- `--lang`：阶段 1 收集的语言（如 `zh`、`en`）
- `--output`：（可选）自定义输出路径，默认为 `output/<topic>/<标题>.epub`

**脚本行为：**
- 第 0 页自动作为封面
- 第 1~N 页按顺序作为章节
- 使用 Fixed-Layout EPUB3 格式（`rendition:layout = pre-paginated`），每张图片占满一整页
- 如果目录中存在 `script.md`（阶段 3 的脚本），自动提取每页文字附在图片下方

**验证：**
- 检查 EPUB 文件是否生成且大小合理
- 输出文件路径和大小

生成完成后，输出最终摘要：
```
绘本生成完成！
📂 output/<topic>/
  ├── characters.md  （角色设定）
  ├── style.md       （风格设定）
  ├── 0.png          （封面）
  ├── 1.png ~ N.png  （正文插图）
  └── <标题>.epub    （电子书）
```

## 阶段间流转规则

```
阶段 1（需求收集）──用户确认──▶ 阶段 2（故事方案）
阶段 2（故事方案）──用户选择──▶ 阶段 3（分页脚本）
阶段 3（分页脚本）──自动执行──▶ 阶段 4（可读性测试）
阶段 4（可读性测试）──用户确认──▶ 阶段 5（角色与风格设定）
阶段 5（角色/风格设定）──用户确认──▶ 阶段 6（Prompt 生成 + 批量生图）
阶段 6（生图验证通过）──自动执行──▶ 阶段 7（生成 EPUB）
```

**流转原则：**
- 阶段 3→4 始终自动衔接（可读性测试是质量闸门）
- 阶段 6→7 始终自动衔接（图片验证通过后直接打包）
- 如果用户初始 Prompt 信息充分，可以连续执行多个阶段，在关键决策点（如阶段 2 选择故事方向）暂停
- 如果用户信息不足，则在每个阶段结束后暂停收集缺失信息
- 阶段 2 结束后必须暂停——用户需要从 3 个故事方向中选择
- 阶段 5 结束后建议暂停——让用户确认角色和风格设定，因为这直接决定所有插图的一致性
